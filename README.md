# sakura-tui

さくらインターネットのサービスをターミナルから操作する TUI（[ratatui](https://ratatui.rs) 製）。

`s` キーでサービスを切り替えて使います（43 種類）。

### コンテナレジストリ
- レジストリの一覧・詳細・作成・編集・削除
- レジストリユーザーの一覧・追加・編集・削除
- イメージ（リポジトリ、タグ、サイズ、レイヤ数、プラットフォーム、ビルド日時）の閲覧と削除

### AppRun（共用型）

> [!IMPORTANT]
> AppRun API を使うには 2 つの前提があります。どちらが欠けても `403 Forbidden` になります。
> 1. **API キーの作成時に「AppRun」の権限にチェック**が入っていること（アクセスレベルとは別の項目です）
> 2. **AppRun のユーザーが作成済み**であること
>    ```sh
>    curl -X POST -u "$SAKURA_ACCESS_TOKEN:$SAKURA_ACCESS_TOKEN_SECRET" \
>      https://secure.sakura.ad.jp/cloud/api/apprun/1.0/apprun/api/user
>    ```
>
> 403 が返ったときは TUI 上にもこの案内を表示します。

- アプリケーションの一覧とステータス
- 公開URL、スケール設定、ポート、デプロイ元のコンテナイメージ
- バージョン一覧とトラフィックの振り分け（`t` で選択中バージョンへ 100%）

### AppRun 専有型（閲覧のみ）
- クラスタの一覧と詳細（ポート、サービスプリンシパル、Let's Encrypt 設定）
- クラスタに属するアプリケーション（稼働中バージョン、台数、クールダウン）
- オートスケーリンググループと、その配下のワーカーノード（状態・draining・世代）
- 証明書（コモンネーム、有効期限）

> [!NOTE]
> 専有型は**閲覧のみ**です。クラスタやポートの作成・変更、証明書の登録はコントロールパネルで行ってください。
> 共用型とは別のエンドポイント（`/cloud/api/apprun-dedicated/1.0`）で、リソース体系も別です。

### サーバー（IaaS）
- ゾーンごとのサーバー一覧（電源状態・プラン・IPアドレス）
- ディスク、NIC、タグを含む詳細
- 起動・シャットダウン・強制停止・強制リセット
- 書き込みモードでは `n` で作成、`D` で削除
  - 作成は CPU・メモリ・OS・ディスクサイズを左右キーで選び、ホスト名・パスワード・SSH公開鍵を指定できます
  - プランは100通り以上あるため、コア数とメモリを別々に選びます。コア数を変えると、その構成で選べるメモリのうち一番近いものへ寄ります
  - 選べる値はゾーンごとにAPIから取得します。OSは Ubuntu / Rocky / AlmaLinux / Debian / MIRACLE LINUX の最新安定版から選べます
  - SSH公開鍵は欄で `Ctrl+K` を押すと、さくらのクラウドに登録済みの鍵・手元の `~/.ssh/*.pub`・GitHub のユーザー名（`github.com/<名前>.keys`）から選べます
  - 削除は接続中のディスクも一緒に消します。起動中は削除できません
- `z` でゾーンを切り替え

### IaaSリソース（閲覧のみ）
- ディスク（容量、プラン、接続方式、接続サーバー、暗号化）
- アーカイブとISOイメージ（容量、スコープ、ストレージ、作成日時）
- ルータ＋スイッチ（帯域、スイッチ、ネットワーク、マスク長、ゲートウェイ）
- パケットフィルタ（ルール数とAllow/Deny、プロトコル、送信元、ポート）
- ブリッジ接続（リージョン、接続スイッチ、サービスクラス）
- ロードバランサ、VPCルータ、データベース、NFSアプライアンス
- GSLB（FQDN、監視方法、ポート、実サーバ数）
- モバイルゲートウェイ（電源状態、接続スイッチ、IPアドレス、インターネット接続）
- エンハンスドロードバランサ（プラン、FQDN、VIP、リージョン、待受ポート、実サーバ）
- ローカルルータ（接続スイッチ、仮想IP、ピア、スタティックルート）
- 一覧には名前、状態、プラン、接続先、IDを表示し、右ペインでサービス固有情報を確認
- ゾーン依存リソースはゾーン切り替えに対応し、全リソースで絞り込みとリソースIDのコピーに対応

### ストレージ・アプリケーション連携（閲覧のみ）
- オブジェクトストレージの全サイトを横断したバケット一覧（サイト、リージョン、S3エンドポイント、プラン）
- シンプルMQのキュー一覧（可視性タイムアウト、未処理メッセージ保存期間）
- イベントバスのスケジュール、トリガー、処理設定（イベントソース、実行間隔、宛先など）
- ワークフロー一覧（公開状態、ログ設定、同時実行モード、タグ）
- シンプル通知の通知先、通知先グループ、ルーティング
- いずれも絞り込み、更新、リソースIDのコピーに対応

### APIゲートウェイ（閲覧のみ）
- 契約、サービス、ルート、ユーザー、グループ、ドメイン、証明書、OIDCをタブで表示
- 選択中サービスのルートと、選択中ユーザーの認証方式を必要なときだけ取得
- Basic / JWT / HMAC の設定概要を表示し、パスワード・秘密鍵・シークレットは取得結果から表示しません
- 絞り込み、更新、リソースIDのコピーに対応

### サービスエンドポイントゲートウェイ（閲覧のみ）
- ゲートウェイと接続先サービスをタブで表示
- 一覧は状態、接続スイッチ、IPアドレス。詳細にネットワーク、DNS転送（ホストゾーン、フォワード先）、モニタリングスイート連携を表示
- 接続先サービスはオブジェクトストレージ、コンテナレジストリ、モニタリングスイート、AppRun専有型コントロールプレーンをエンドポイント単位の行に展開。エンドポイントを指定できない種別は「自動設定」と表示
- 全ゾーンで提供されるため、`z` のゾーン切り替えに対応
- 絞り込み、更新、リソースIDのコピーに対応

### ネットワークスイート (CR)（閲覧のみ）
- サブネットグループ、サブネット、アドレスをタブで表示
- サブネットグループを選ぶとその配下のサブネット、サブネットを選ぶと払い出し済みアドレスを表示
- 各リソースは数値IDを持たずSRN（`srnv1:...`）で参照し合うため、一覧のID列にはSRN末尾のIDを、`y` でのコピーにはSRN全体を渡します
- 受付ゾーンは石狩第3（is1c）に固定です。他ゾーンへ問い合わせると500が返るため、ゾーン切り替えの対象外にしています。問い合わせ先は画面のタイトルに表示します
- NIC接続（インターフェースコネクション）は取得APIが提供されていないため未対応です
- 絞り込み、更新、リソースIDのコピーに対応

### AI Engine
- モデルとドキュメントをタブで表示（推論APIとRAGは同じトークンを使うため1つのサービスにまとめています）
- モデルタブ: 利用可能なモデル一覧。モデルID、種別、提供元、説明、コンテキスト長、対応機能を確認
- ドキュメントタブ（RAG・閲覧のみ）: 上段に一覧と詳細、下段に選択中ドキュメントのチャンク本文。処理状態（待機中・処理中・利用可能・削除済み・エラー）、埋め込みモデル、チャンク数、タグを表示し、エラーのときは詳細に理由を出します
- チャンク本文はチャンクごとの区切り見出し付きで通して読めます。`J` / `K` でスクロール（`↑↓` はドキュメント一覧の選択に使うため）
- 書き込みモードでは `n` でアップロード、`e` で名前とタグの変更、`d` で削除ができます。削除は元に戻せないため名前の入力を求めます
- RAGに「データセット」という区分はAPIに無く、グルーピングはタグで行います
- `t` で名前付きアカウントトークンを複数登録し、使用・更新・コピー・削除
- アプリで登録した各トークンはクラウドAPIプロファイルごとにOSのキーチェーンへ保存
- `SAKURA_AI_ENGINE_TOKEN` 環境変数にも対応
- トークンの新規発行・サービス側での失効はAI Engineコントロールパネルで行います

### CDN・自動運用・マネージドDB（閲覧のみ）
- ウェブアクセラレータのサイト一覧（状態、ドメイン、オリジン、キャッシュTTL、証明書）
- オートスケール設定（トリガー、対象ゾーン、停止状態、登録元）
- エンハンスドデータベース（DB種別、リージョン、ホスト、ポート）
- 自動バックアップ（対象ディスク、世代数、取得曜日、対象ゾーン）
- いずれも絞り込み、更新、リソースIDのコピーに対応

### NoSQL（閲覧のみ）
- DB、ノード、バックアップ、パラメータをタブで表示
- DB一覧は状態、プラン、ノード数、Cassandraのバージョン。詳細に接続先IP、ポート、既定ユーザー、接続元ネットワーク、バックアップ設定、リペア設定、ディスク暗号化を表示
- ノードは全体の健全性と更新可能なバージョンに加えて、プライマリノードと追加ノードを1つの表に統合して表示
- バックアップは取得日時、サイズ、削除・復元の進行状況
- パラメータは既定値から変更されている項目だけ現在値の列に表示
- 東京第2ゾーン（tk1b）限定のサービスのため、ゾーン切り替えの対象外です。問い合わせ先ゾーンは画面のタイトルに表示します
- 絞り込み、更新、リソースIDのコピーに対応

### スイッチ
- ゾーンごとのスイッチ一覧
- 名前、説明、ID、タグ、作成日時
- 接続中のサーバー数とアプライアンス数
- スイッチの作成・編集・削除（接続中のリソースがある場合は削除を停止）
- `z` でゾーンを切り替え

### DNS
- ゾーン一覧とレコード（名前・種別・値・TTL）
- 委任先のネームサーバー
- DNSゾーンの作成・説明編集・削除
- レコードの追加・編集・削除（設定ハッシュによる更新競合の検出）

### シンプル監視
- 監視の一覧（有効/停止、監視対象、種別、間隔）
- プロトコル・ポート・パス・期待ステータス・通知先
- ping / TCP / HTTP / HTTPS監視の作成・編集
- 監視の有効／停止切り替えと削除

### シークレットマネージャ
- Vault 一覧とシークレット名・最新バージョン
- Vaultの作成・編集・削除
- シークレットの登録・新バージョン登録・削除
- 値は一覧では常に伏せ字。`u` を押して確認ダイアログに答えたときだけ取得します

### KMS（閲覧のみ）
- KMS鍵の一覧、状態、サービスクラス、鍵の由来、最新バージョン、タグ
- 絞り込み、更新、リソースIDのコピーに対応

### IAM
- ユーザー、グループ、プロジェクト、IAMロール、サービスプリンシパルの一覧と詳細
- OTP・セキュリティキーの設定状態、所属プロジェクト、ロールカテゴリと付与可能階層を表示
- ユーザー、グループ、プロジェクト、サービスプリンシパルの作成・編集・削除
- プロジェクトIAMポリシーへのプリセットロール付与・解除（ユーザー、グループ、サービスプリンシパル）
- パスワードや秘密鍵などの機密値は一覧で取得・表示しません。入力したパスワードも保存しません

### クラウドHSM（閲覧のみ）
- HSM、クライアント、ライセンス、ドキュメントをタブで表示
- HSMは状態、IPアドレス、ネットワーク、ローカルルータ。クライアントは詳細パネルに証明書（公開鍵側）を表示
- ライセンスを選ぶと、そのライセンスのドキュメント一覧を表示
- ゾーンごとに配置されるため、`z` のゾーン切り替えに対応
- ピア（`/peers`）は仕様側のスキーマが未整備で、GETがピア一覧ではなくHSM本体を返す定義のため未対応です
- 絞り込み、更新、リソースIDのコピーに対応

### セキュリティコントロール（閲覧のみ）
- 評価ルールと自動アクションをタブで表示
- 評価ルールは有効・無効、評価対象（ゾーンまたはオブジェクトストレージサイト）、必要なIAMロール、説明。空欄は「すべて対象」の意味です
- 自動アクションは名前、有効・無効、種別（シンプル通知／ワークフロー）、宛先。詳細に実行条件（CEL式）を表示
- プロジェクトの有効化状態（有効・無効、サービスプリンシパル、自動アクション上限）を評価ルールタブの先頭に表示
- 評価結果（検出内容）を取得するAPIは公開されていないため表示できません。コントロールパネルのイベントログで確認してください
- 絞り込み、更新、リソースIDのコピーに対応

### モニタリングスイート
- アラートプロジェクトとルール（発報中かどうかを色分け）
- アラートプロジェクトの作成・編集・削除
- アラートルールの作成・編集・削除（警告／重大しきい値と継続時間）
- ログ計測ルールの作成・編集・削除（公式v1マッチャーJSONを完全保持）
- クラウドリソースからログストレージへの転送設定の作成・編集・削除
- クラウドリソースからメトリクスストレージへの転送設定の作成・編集・削除
- 転送元のパブリッシャー／バリアントをAPIから取得して選択
- ダッシュボードプロジェクトの作成・編集・削除
- 発報履歴（深刻度・継続中/復旧・値としきい値）
- シンプル通知／EventBusの通知先と、再送間隔・ラベル条件付き通知経路の作成・編集・削除
- 通知経路を `[` / `]` で上下に並べ替え
- ログ／メトリクス／トレースの保管先
- ログ／メトリクス／トレースストレージの作成・名前／説明編集・削除
- ログ／トレースストレージの保持期間変更
- ストレージアクセスキーの作成・説明編集・削除と、確認後のシークレット表示
- アクセスキーはユーザ領域ストレージだけが対象（システム領域ではAPIを呼びません）

### 共通
- サービス切り替えは独立した全画面ページで、カテゴリ／サービスの2ペイン表示。`←` / `→` でカテゴリ、`↑` / `↓` でサービスを選択
- リストの絞り込み（`/`）、選択項目のクリップボードへのコピー（`y`）
- usacloud プロファイルの切り替え（`p`）

起動時は**読み取り専用モード**です。書き込み系の操作は `w` キーで明示的にモードを切り替えてから行います。
通常起動では最初にサービス選択画面を表示します。`--service` を指定した場合だけ、そのサービスを直接開きます。

## インストール

```sh
cargo build --release
./target/release/sakura-tui
```

### 開発時のフック

push する前に整形・lint・テストを通すフックを用意してあります。
クローンし直したときは一度だけ有効にしてください。

```sh
git config core.hooksPath .githooks
```

`cargo fmt --check` → `cargo clippy`（警告もエラー扱い）→ `cargo test` を順に実行し、
一つでも落ちれば push を中止します。合計で3秒ほどです。
急ぐときは `git push --no-verify` で飛ばせます。

### コマンドラインオプション

```
  -p, --profile <名前>   使う認証情報（usacloud プロファイル / キーチェーン）

  -z, --zone <ゾーン>     ゾーン依存のサービスで使うゾーン (例: is1a)
  -s, --service <名前>    起動時に開くサービス
                         server / disk / registry / apprun / dedicated /
                         archive / iso-image /
                         switch / internet / packet-filter / bridge /
                         loadbalancer / enhanced-loadbalancer / vpcrouter /
                         gslb / mobile-gateway / local-router /
                         database / nfs / object-storage / simplemq /
                         simple-notification / kms / iam /
                         enhanced-db / ai-engine / eventbus / workflows / api-gateway /
                         webaccel /
```

`--trace` は TUI が画面を占有するため、`sakura-tui --trace 2>trace.log` のように
リダイレクトして使います。

## 認証

### さくらのクラウド API

以下の順で探します。

1. 環境変数
   ```sh
   export SAKURA_ACCESS_TOKEN=xxxxxxxx          # SAKURACLOUD_ACCESS_TOKEN も可
   export SAKURA_ACCESS_TOKEN_SECRET=xxxxxxxx   # SAKURACLOUD_ACCESS_TOKEN_SECRET も可
   ```
2. usacloud のプロファイル（`~/.usacloud/<プロファイル名>/config.json`）

   プロファイル名は `SAKURA_PROFILE` / `SAKURACLOUD_PROFILE` / `USACLOUD_PROFILE`、
   指定がなければ `~/.usacloud/current` の内容、それも無ければ `default` を使います。
   既に `usacloud config` を済ませていれば設定不要です。
3. キーチェーンに預けた資格情報

   前回アプリ内で選んだものを覚えているので、そこから再開します。
   記録が無いか、その資格情報が消えている場合は、残っているものの先頭を使います。

いずれも見つからない場合でもアプリは終了せず、初期設定フォームを表示します。
名前・アクセストークン・シークレット・既定ゾーン・保存先を入力すると、検証後に保存して
そのままサービス選択画面へ進みます。

`--profile <名前>` を渡すと、usacloud のプロファイルとキーチェーンに預けた資格情報の
どちらからでも名前で選べます。同名が両方にある場合は usacloud を採るので、
キーチェーン側を明示したいときは `--profile @keychain:<名前>` と書いてください。
名前が見つからないときは、使える名前を並べて終了します。

起動後は `p` キーでピッカーを開き、環境変数・usacloud プロファイル・キーチェーンに預けた
資格情報のあいだを切り替えられます。切り替えはそのセッション限りで、
`~/.usacloud/current` は書き換えません。

### IAM API

IAM APIは通常のAPIキーではなく、サービスプリンシパルのBearer認証を使用します。
IAM画面で `a` キーを押し、以下を登録してください。

- サービスプリンシパルのリソースID
- サービスプリンシパルキーのキーID
- キー作成時の公開鍵と対になるPEM形式のRSA秘密鍵

保存前にBearerトークンの発行とユーザー一覧の取得を行い、認証と参照権限を検証します。
識別情報は設定ファイル、RSA秘密鍵はOSのキーチェーンに保存します。ユーザー一覧の閲覧には
IDポリシーの「ID閲覧者」以上、ユーザーやグループの変更には「ID管理者」が必要です。
プロジェクトのIAMロールを付与・解除する場合は、対象プロジェクトのIAMポリシーを編集できる
「オーナー」等のロールも必要です。

CIなどでは、公式SDKと同じ環境変数も利用できます。

```sh
export SAKURA_SERVICE_PRINCIPAL_ID=...
export SAKURA_SERVICE_PRINCIPAL_KEY_ID=...
export SAKURA_PRIVATE_KEY='-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----'
```

ピッカー内のキー:

| キー | 動作 |
| --- | --- |
| `Enter` | 選択した資格情報に切り替え |
| `n` | 資格情報を新規作成 |
| `c` | 表示色を割り当て（似た名前を見分けるため） |
| `d` | 削除（キーチェーンに保存したもののみ） |

### 資格情報の新規作成

初回起動時、または `p` → `n` で作成フォームが開きます。名前・アクセストークン・シークレット・既定ゾーンを入力し、
保存先を選びます。**保存前に API を 1 回呼んでトークンが通ることを確かめる**ので、
打ち間違えたトークンが保存されることはありません。

| 保存先 | 保存場所 | 他ツールとの共用 | 平文 |
| --- | --- | --- | --- |
| usacloud 互換 | `~/.usacloud/<名前>/config.json`（0600） | usacloud CLI / Terraform / Packer から使える | 残る |
| キーチェーン | OS のキーチェーン + 設定ファイルに名前とゾーンのみ | この TUI からのみ | 残らない |

> [!NOTE]
> `~/.usacloud` は `sacloud/api-client-go` が読む共通の場所で、usacloud CLI のほか
> Terraform provider や Packer plugin も同じ仕組みを使います。キーチェーンを選ぶと
> 平文は残りませんが、それらのツールからはその名前で認証できなくなります。
>
> 削除できるのはキーチェーンに保存したものだけです。usacloud のプロファイルは
> 他のツールも使うため、この TUI からは消しません。

### コンテナレジストリ（イメージ一覧）

イメージ一覧はクラウド API では取得できないため、レジストリの FQDN に対して
Docker Registry HTTP API V2 を直接呼びます。そのため **クラウド API のトークンとは別に、
レジストリユーザーの ID / パスワード** が必要です。

イメージタブで `L` を押すとログインダイアログが開きます。「設定に保存」を有効にすると
次回以降は自動でログインします。

**パスワードは OS のキーチェーンに保存され、設定ファイルには書き込みません。**
macOS はキーチェーン、Windows は資格情報マネージャー、Linux は Secret Service を使います。
設定ファイルに残るのはユーザー名だけです。

```toml
[registries."example.sakuracr.jp"]
username = "your-registry-user"
```

`O` キーで破棄すると、設定ファイルとキーチェーンの両方から消えます。
設定ファイルの場所は `SAKURA_TUI_CONFIG` で変更できます。

> [!NOTE]
> 以前のバージョンが設定ファイルに平文で保存したパスワードは、起動時に自動でキーチェーンへ移し、
> 設定ファイルからは削除します。
>
> キーチェーンが使えない環境（Secret Service の無いサーバなど）では、平文へ退避せず
> **保存自体を行いません**。その場合ログイン情報は起動中のみ有効です。

### 操作モード

事故を防ぐため、起動時は**読み取り専用モード**です。ヘッダーに現在のモードが出ます。

| モード | 表示 | できること |
| --- | --- | --- |
| 読み取り専用（既定） | `読取専用`（緑） | 閲覧、絞り込み、コピー、レジストリへのログイン |
| 書き込み | `書込可`（赤・反転） | 上記に加えてユーザー管理、レジストリ / スイッチ / DNS / シンプル監視の管理、イメージ削除、トラフィック切替、サーバーの電源操作 |

読み取り専用のあいだは書き込み系のキーが無効になり、キーヒントにも出ません。
レジストリへのログイン（`L`）はイメージの閲覧に必要なため、読み取り専用でも使えます。

### 危険な操作について

- **レジストリの削除**（`D`）は取り消せず、保存されている全イメージとユーザーが消えるため、
  確認ダイアログでレジストリ名の入力を求めます。
- **スイッチの削除**（`D`）は確認ダイアログを表示し、サーバーまたはアプライアンスが
  接続されている場合は API に送信せず停止します。
- **DNSレコードの削除**（レコードペインの `d`）は確認ダイアログを表示します。
  更新時に設定ハッシュを送るため、別の場所で先に変更されていれば競合として停止します。
- **DNSゾーンの削除**（ゾーンペインの `D`）は全レコードも復元不能になるため、
  確認ダイアログでゾーン名の入力を求めます。
- **シンプル監視の削除**（`D`）は確認ダイアログを表示します。
- **Vaultの削除**（Vaultペインの `D`）は課金停止を伴うため、Vault名の入力を求めます。
- **シークレットの削除**（シークレットペインの `d`）は全バージョンが対象のため、シークレット名の入力を求めます。
- **アラートプロジェクトの削除**（`D`）はプロジェクト名の入力を求めます。
- **アラートルールの削除**（ルールペインの `d`）はルール名の入力を求めます。
- **ログ計測ルールの削除**はログからのメトリクス生成を停止するため、ルール名の入力を求めます。
- **ログ転送設定の削除**は対象リソースからのログ収集を停止します。確認ダイアログを表示します。
- **通知先の削除**は、参照中の通知経路がある場合APIに拒否されます。先に通知経路を削除してください。
- **通知経路の削除**後は、一致するアラートがその経路から通知されなくなります。
- **モニタリングストレージの作成**は作成後に課金対象になります。削除時はストレージ名の入力を求めます。
- **ストレージ保持期間**を41日以上にすると追加料金が発生するため、変更前に確認します。
- **ストレージアクセスキーの削除**後は、そのキーを使う送信処理が認証できなくなります。
- **イメージの削除**（イメージタブのタグペインで `d`）は Registry API の仕様上
  マニフェスト単位で行われるため、**同じダイジェストを指す他のタグも同時に消えます**。
  レジストリ側で削除が無効な場合は `405 Method Not Allowed` になります。
- **サーバーの強制停止 / 強制リセット**（`X` / `B`）は電源ケーブルを抜くのと同じで
  データが失われることがあるため、サーバー名の入力を求めます。
  通常のシャットダウン（`x`）と起動（`b`）は確認ダイアログのみです。
  現在の電源状態と噛み合わない操作（起動中のサーバーへの起動など）は API を叩く前に止めます。

## 構成

全体の構造は [`docs/sakura-tui-architecture.html`](docs/sakura-tui-architecture.html) にまとめてあります。
ブラウザで開くと、入力と描画のループ、共通クライアントと専用クライアントの分かれ方、
認証とエンドポイントの3つの流れを順に追えます。
図の元データは [`docs/sakura-tui.architecture.json`](docs/sakura-tui.architecture.json) です。

| ファイル | 役割 |
| --- | --- |
| `src/config.rs` | 認証情報の読み込み（環境変数 / usacloud プロファイル）と設定ファイルの保存 |
| `src/ai_engine.rs` | AI Engineのモデル一覧クライアント（Bearer認証） |
| `src/sacloud.rs` | さくらのクラウド API v1.1 クライアントの土台とコンテナレジストリ |
| `src/iaas.rs` | ゾーンとサーバー（電源操作・作成・削除、プランとOSテンプレートの選択肢） |
| `src/pubkey.rs` | サーバー作成に入れる SSH 公開鍵の取得元（`~/.ssh/*.pub` と GitHub） |
| `src/switch.rs` | ゾーンごとのスイッチ一覧と件数 |
| `src/cloud_resources.rs` | ディスク、ルータ＋スイッチ、IaaSアプライアンスの共通閲覧クライアント |
| `src/managed_resources.rs` | AI Engineモデルやオブジェクトストレージなどの共通一覧・詳細モデル |
| `src/apprun.rs` | AppRun 共用型 API クライアント |
| `src/apprun_dedicated.rs` | AppRun 専有型 API クライアント（閲覧のみ、カーソル方式のページング） |
| `src/api_gateway.rs` | APIゲートウェイの契約、サービス、ルート、認証関連リソースの閲覧クライアント |
| `src/nosql.rs` | NoSQLのDB、ノード、バックアップ、パラメータの閲覧クライアント |
| `src/seg.rs` | サービスエンドポイントゲートウェイと接続先サービスの閲覧クライアント |
| `src/security_control.rs` | セキュリティコントロールの有効化状態・評価ルール・自動アクションの閲覧クライアント（カーソル方式のページング） |
| `src/cloudhsm.rs` | クラウドHSMのHSM・クライアント・ライセンス・ドキュメントの閲覧クライアント |
| `src/networking_suite.rs` | ネットワークスイート (CR) のサブネットグループ・サブネット・アドレスの閲覧クライアント |
| `src/ai_rag.rs` | AI Engine RAG のドキュメント・チャンクの閲覧クライアント（`src/ai_engine.rs` と同じホスト・同じBearer認証） |
| `src/commonservice.rs` | DNS とシンプル監視（コンテナレジストリと同じ commonserviceitem） |
| `src/secretmanager.rs` | シークレットマネージャ（値の取得は明示操作のときだけ） |
| `src/monitoring.rs` | モニタリングスイート（アラート・保管先） |
| `src/registry.rs` | Docker Registry HTTP API V2 クライアント（Bearer / Basic 認証に対応） |
| `src/http.rs` | リトライ（429・5xx・接続エラー）とトレースログの共通処理 |
| `src/keychain.rs` | レジストリのパスワードを OS のキーチェーンに預ける |
| `src/app/` | 画面状態とキー入力。`mod.rs` が共通部分、サービスごとに `apprun.rs` / `dedicated.rs` / `server.rs` / `switch.rs` |
| `src/ui/` | 描画（サービスごとのビューと共通のダイアログ） |

API 呼び出しは全て `tokio::spawn` して結果をチャネルで受け取るため、通信中も UI は止まりません。
一時的な失敗（429・5xx・接続エラー）は指数バックオフで最大3回まで送り直します。
`Retry-After` ヘッダがあればその指示に従います。

## 制限

- コンテナレジストリ、AppRun、シークレットマネージャ、マネージドサービス群はゾーンに依存しません。ゾーン切り替えはIaaSリソースとモニタリングスイートに効きます。
- さくらのクラウド API は GET のリクエストボディを読まないため、検索条件はクエリ文字列で送っています。
- 公開設定（`public`）は表示のみです。さくら側で廃止予定の項目のため、作成時は常に「非公開」になります。
- タグの詳細（サイズ・レイヤ数など）は選択中のタグの分だけ取得します。
- AppRun（共用型）はアプリの作成・削除・デプロイには未対応です（閲覧とトラフィック切替のみ）。
- AppRun（専有型）は閲覧のみです。ロードバランサとサービスクラスの一覧は未対応です。
- APIゲートウェイは閲覧のみです。パスワード、秘密鍵、JWT／HMACシークレット、証明書秘密鍵は表示しません。
- NoSQLは閲覧のみです。東京第2ゾーン（tk1b）でのみ提供されるサービスのため、ゾーン切り替えの対象外です。作成・削除・電源操作・リペア実行・バックアップ復元・バージョン更新・ノード追加には未対応です。
- サービスエンドポイントゲートウェイは閲覧のみです。作成・変更・削除・設定反映・電源操作・リセットには未対応です。1件取得・電源状態取得・インターフェース取得のAPIは、いずれも一覧に含まれる情報の部分集合のため呼んでいません。
- セキュリティコントロールは閲覧のみです。有効化・無効化、評価ルールの変更、自動アクションの作成・変更・削除には未対応です。評価結果を取得するAPIは公開されていないため、検出内容はコントロールパネルのイベントログで確認してください。
- クラウドHSMは閲覧のみです。作成・変更・削除、ピアの接続・切断、ドキュメントのダウンロードには未対応です。利用には事前審査と専用の権限が必要です。
- 自動バックアップは閲覧のみです。バックアップの実行結果（世代ごとの成否）を取得するAPIは無いため、取得済みアーカイブはアーカイブ画面で確認してください。
- ネットワークスイート (CR) は閲覧のみです。サブネットグループ・サブネットの作成・変更・削除、NIC接続の接続・切断には未対応です。NIC接続は取得APIが仕様に無く、IaaSのサーバー情報から組み立てる必要があるため一覧できません。
- AI EngineのRAG機能は、ドキュメントのアップロード・名前とタグの変更・削除に対応しています。モデルと分割サイズは取り込み時に決まるため変更できません。ベクトル検索とチャットには未対応です。ドキュメント全文は個別取得APIにしかありませんが、同じ本文をチャンク単位で見られるため取得していません。
- AI Engineのモデル一覧はOpenAI互換の `/v1/models` を利用します。トークンの発行・失効APIは公開されていないため、サービス側の管理はコントロールパネルで行います。
- DNSゾーン名はサービス仕様上、作成後に変更できません。編集できるのは説明のみです。
- シンプル監視の編集フォームは ping / TCP / HTTP / HTTPS に対応します。その他の方式は閲覧・有効／停止・削除のみ対応します。
- モニタリングスイートの専有プラン作成時の暗号化・KMS・サービスプリンシパル指定は未対応です。
- スイッチに対するサーバーやアプライアンスの接続・切断操作には未対応です。
- サーバーの作成では、共有セグメントに接続した NIC を1つ持つ構成のみ作れます。スイッチへの接続、追加NIC、パケットフィルタ、スタートアップスクリプトには未対応です。
- サーバーのプラン変更、ディスクの単体作成・接続変更には未対応です。
- サーバー作成の SSH 公開鍵は、選んだ鍵をそのままディスクの初期設定に渡します。さくらのクラウドへの鍵の登録・削除には未対応です。
- ディスクは作成した時点から、サーバーは起動した時点から課金されます。動作確認にはサンドボックスゾーン（tk1v）が使えます（課金されませんが、サーバーは実際には動作しません）。
